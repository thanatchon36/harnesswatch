\section{Background: Anatomy of a Harness}\label{sec:background}
\answers{Covers the descriptive part of RQ1 and prepares RQ2}

\paragraph*{The loop} A harness assembles a context, calls the model, checks each proposed tool call against a permission policy, executes it and returns the result to the model. Repository content, tool output and MCP results flow inwards; commands and network requests flow outwards.

\paragraph*{Repository files} Harnesses auto-load instruction files (\texttt{AGENTS.md}, \texttt{CLAUDE.md}, \texttt{.github/copilot-instructions.md}, \texttt{.cursor/rules}), settings that can set environment variables, permission modes and \emph{hooks} (shell commands bound to lifecycle events), and MCP declarations (\texttt{.mcp.json}, \texttt{.vscode/mcp.json}). Formats are shared across products: Grok Build imports Claude Code and Cursor hook and MCP files\evD~\cite{grokbuild_hooks,grokbuild_mcp}. A cloned repository is therefore configuration as well as data.

\paragraph*{Permissions and sandbox} Permission modes range from ``ask before every tool call'' to ``approve everything'' (YOLO, bypass, full-auto, always-approve), with allow and deny rules over commands and paths. Several harnesses now default to a model-based approver; Claude Code starts \texttt{claude -p} in a classifier-mediated \texttt{auto} mode when feature flags are not fetched\evD\evT~\cite{cc_permission_modes}. Some confine commands within an OS sandbox (Seatbelt, bubblewrap, Landlock) or a container\evD~\cite{cc_sandboxing}. Approval decides \emph{whether} an action runs; the sandbox bounds \emph{what it can reach}.

\paragraph*{Extensions, state and headless mode} MCP servers~\cite{mcpspec} are launched locally, often through unpinned \texttt{npx} or \texttt{uvx}, or reached remotely, and their tool descriptions enter the context verbatim; skills and plugins add further code and prompts from marketplaces. Credentials, transcripts and persistent memory reside in a per-user state directory, and sub-agents may inherit the parent's permissions. Every harness we benchmarked runs non-interactively\evD\evT{} (\texttt{claude -p}, \texttt{codex exec}, \texttt{grok -p}, \texttt{copilot -p}); in CI the triggering issue or pull request may be attacker-controlled and the job may hold secrets.
