\section{Scope, Tiers and Evidence Method}\label{sec:method}
\answers{Describes how the evidence behind RQ2--RQ7 was collected}

\paragraph*{Tiers by method} We group harnesses by what can be observed about them, not by market share.
\emph{Tier~A} (open source; white-box): we read the source at a pinned commit and run the client in containers (e.g.\ Codex CLI, OpenCode, Gemini CLI, Qwen Code, Aider, goose, Cline, Hermes Agent).
\emph{Tier~B} (closed but runnable; black-box): we install the official client in a disposable container, record what it writes and which hosts it contacts, and drive it headless (Claude Code, GitHub Copilot CLI, and the Antigravity CLI before login). Grok Build is a hybrid: its source is public under Apache-2.0\evD~\cite{grokbuild_repo}, but the public tree lags the npm release (1.0.45 against 1.0.52) and endpoints are injected at build time, so we read the source white-box and treat the shipped npm client as Tier~B in E3 and E7.
\emph{Tier~C} (closed and unreachable): documentation, advisories and third-party research only (e.g.\ Cursor, Kiro, Devin, Jules).
\emph{Tier~D} (runtimes and SDKs) has its own ladder and is never ranked against products; the rubric and figures group it with hosted services as ``tier~C''. The matrix covers \nHarnessesAB{} tier A/B products and \nHarnessesC{} runtimes and hosted services.

\paragraph*{Black-box method} For a closed harness we install the official release, read its documentation and advisories, parse its configuration, run it under \texttt{harnesswatch observe} (Section~\ref{sec:tool}), probe its treatment of configuration with synthetic repositories carrying hooks, MCP servers and settings, and inspect its package metadata. We never decompile, deobfuscate or consult leaked source, never decrypt TLS or store request bodies, and remain within vendor terms; otherwise the cell is \emph{N/A (terms)}. No vendor login was placed in any container: closed clients were driven solely through documented custom-endpoint features pointing at a local model, namely Claude Code's \texttt{ANTHROPIC\_BASE\_URL}, Copilot CLI's bring-your-own-key mode, which requires no GitHub authentication\evD~\cite{copilot_byok}, and Grok Build's custom models\evD~\cite{grokbuild_overview}. Anthropic states that it ``doesn't support routing Claude Code to non-Claude models through any gateway''\evD~\cite{cc_llm_gateway}, so our Claude Code runs characterise harness behaviour in an unsupported configuration, not vendor-supported performance. Antigravity has no documented local-model path and its terms restrict use with other products\evD~\cite{ag_terms}, so it was observed only before login.

\paragraph*{Evidence labels} Every factual statement about a harness carries one of three labels, rendered as superscripts:
\evT~\emph{verified-by-test}, behaviour or state observed by running the pinned client;
\evD~\emph{from-official-docs}, vendor documentation, vendor advisories, registry metadata or the official source code (reading source counts as documentation, not as a test);
\evTP~\emph{third-party-report}, a write-up by an independent researcher or journalist.
Unverified claims are excluded. Documentation and source facts are recorded in the evidence ledger and in \texttt{matrix/evidence/}; every \evT{} fact traces to a probe or bench file under \texttt{experiments/results/} or \texttt{bench/results/}.

\paragraph*{Use of generative AI} The study was carried out with Claude (Anthropic), operated through the Claude Code harness, which is itself among the systems examined. Working from the author's written specification, LLM research agents wrote the \tool{} toolkit and the experiment scripts, collected the evidence, produced both matrix ratings, collected and classified the incidents, and drafted and revised this manuscript. The author specified the research questions, the scope, the rules of evidence and the ethical constraints, directed the work and reviewed its outputs, and takes sole responsibility for the content; Section~\ref{sec:limits} discusses the consequences for reliability.

\paragraph*{Kinds of finding} We distinguish a \emph{vulnerability} (a defect that violates the product's own security intent, usually with a CVE or GHSA), a \emph{design weakness} (a documented default or capability that enables harm without being a bug, such as headless mode running repository hooks) and a \emph{policy choice} (e.g.\ telemetry or retention defaults). Only the first is a bug.

\paragraph*{Ethics} Experiments ran in disposable containers on the author's machine with inert canaries and synthetic secrets; the public-repository study stores aggregates only. Issues that might be unknown to the vendor went to private coordinated disclosure and are not described here. Packages were examined through registry metadata alone; one fact obtained by listing the strings in a binary was withdrawn as outside that rule, and the reported source-map exposure in Claude Code's npm release 2.1.88 of 31 March 2026\evTP~\cite{cc_sourcemap2026} is cited only as an event, with no use of the exposed material.
