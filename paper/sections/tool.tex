\section{Design of \texttt{harnesswatch}}\label{sec:tool}
\answers{Covers the design half of RQ4 and the instrument used for RQ5 and RQ7}

\tool{} is an Apache-2.0 Python package and command-line tool. It is read-only and offline by default, never transmits file contents, and redacts every secret it reports.

\paragraph*{Profiles and a common schema} One risk has many spellings: approve-everything is \texttt{bypassPermissions} in Claude Code, \texttt{approval\_policy = "never"} in Codex, \texttt{yolo} in Gemini and Qwen, and \texttt{"permission": "allow"} in OpenCode. A YAML profile for each of the \nHarnesses{} harnesses in the matrix records file locations, key names and documented defaults, and a profile-driven parser maps every file onto a common \texttt{HarnessConfig} model (permission mode, allow and deny lists, hooks, MCP servers, instruction files, trust, telemetry and auto-update). A file shared by several harnesses is parsed once, with the semantics of the format's owner.

\paragraph*{Audits and rules} Six audit modules cover \emph{config}; \emph{mcp} (pinning, transport, inline secrets, tool-description injection, auto-approval); \emph{instructions} (hidden Unicode, override phrasing, remote includes); \emph{secrets} (state directories, transcripts, file modes); \emph{supply} (SBOM, OSV, installer verification); and \emph{ci} (headless agents on untrusted triggers). Each of the \nESixRules{} rules (Table~\ref{tab:rules}) carries a severity, a confidence, a kind (vulnerability pattern, design weakness or policy choice), taxonomy classes, remediation guidance and \texttt{should\_fire}/\texttt{should\_not\_fire} fixtures. Output is terminal, JSON, Markdown or SARIF~2.1.0; a GitHub Action and a pre-commit hook wrap the repository audits.

\paragraph*{observe and bench} \texttt{harnesswatch observe <harness> -- CMD} runs a command in a disposable container whose sole exit is a logging proxy, and records the CONNECT targets (classified as model API, telemetry, update or unknown), a filesystem diff with modes, credential locations, sandbox evidence from \texttt{/proc} and any permission prompts in the output. It stores no request bodies and does not decrypt TLS. It underlies E5, E7 and every bench run. The canary bench (Section~\ref{sec:eval-bench}) drives each harness headless through a dedicated adapter and aggregates rates with Wilson intervals~\cite{wilson1927}.
