\section{Comparative Analysis of Security Controls}\label{sec:controls}
\answers{RQ2}

\paragraph*{Rubric} We score 15 control dimensions from 0 to 3: D01 permission model, D02 execution sandbox, D03 network egress, D04 workspace and configuration trust, D05 MCP governance, D06 extensions and plugins, D07 secrets and credential storage, D08 headless and CI safeguards, D09 persistent memory, D10 sub-agent isolation, D11 audit logging, D12 telemetry and retention, D13 distribution supply chain, D14 managed policy, D15 vulnerability disclosure. The scale is 0~absent, 1~opt-in or weak, 2~default-on with documented gaps, 3~strong, documented and centrally enforceable, with per-dimension criteria (Appendix~\ref{app:rubric}). Only \evD{} and \evT{} facts can raise a score and \evTP{} facts can only lower it (third-party reports document bypasses, not guarantees); the highest level whose criteria are \emph{all} met is chosen; undecidable criteria count as unmet; incident history does not change scores (it belongs to RQ3). D12 records a policy choice, not a vulnerability. Means are unweighted, need at least 8 scored dimensions and are shown with the minimum; rankings are claimed only if they hold under equal, incident-exposure and security-core weightings.

\paragraph*{Coverage and reliability} Of \nCells{} harness--dimension cells, \nCellsScored{} were scored and \nCellsNA{} are N/A with a recorded reason (feature absent, no access, or not documented); \nInsufficientEOne{} runtimes have too little evidence for a mean. A second LLM-agent rater, without access to the first rater's scores, rescored the matrix from the \emph{same} extracted fact lists, so agreement measures how consistently the rubric is applied to shared evidence, not the reliability of evidence collection. On the \nOverlapEOne{} cells both scored, quadratic-weighted Cohen's $\kappa$~\cite{cohen1968} is \kappaEOne{}, exact agreement \exactEOne{} and within-one agreement \withinOneEOne{}; these exclude the \naVsScoreEOne{} cells where one rater gave N/A and the other a score. All \nDisagreeEOne{} disagreements (including those N/A cases) are published, not adjudicated, and rater~1's scores are reported.

\paragraph*{Overall picture} Controls exist but are rarely safe by default (Figure~\ref{fig:heatmap}). Across the \nRankedAB{} tier A/B products the per-dimension mean never reaches 2; the lowest are network egress (D03, mean \dimABMeanThree{}), the execution sandbox (D02, \dimABMeanTwo{}), headless and CI safeguards (D08, \dimABMeanEight{}) and workspace trust (D04, \dimABMeanFour{}). The highest are vulnerability disclosure (D15, \dimABMeanFifteen{}), audit logging (D11, \dimABMeanEleven{}) and managed policy (D14, \dimABMeanFourteen{}). Means differ little: only Codex CLI stays in the top three and only Continue in the bottom three under all weightings, so buyers should read per-dimension columns, not means.

\paragraph*{Permission model (D01)} Nearly every product offers per-action approval, but only \dimABTwoPlusOne{} of \nRankedAB{} reach score~2. Two patterns hold scores down: approve-everything can often be switched on from repository-controlled files (hooks returning an auto-approve verdict, repository MCP entries with \texttt{autoApprove}), and several harnesses default to a model-based approver (Claude Code's \texttt{auto}\evD{}, Cursor's auto-review\evD{}, Qwen Code's AUTO\evD{}, Hermes Agent's \texttt{smart}\evD{}). The rubric does not count a classifier verdict as ``asking'', so these defaults score~1; counting them as asking would raise Claude Code's D01 from 1 to 3 and would also lift the other classifier-default harnesses. We did not recompute rankings under that reading; it is the main open question for the rubric.

\paragraph*{Sandbox and egress (D02, D03)} These are the lowest-scoring dimensions (means \dimABMeanTwo{} and \dimABMeanThree{}). Among tier A/B products, \dimABZeroTwo{} have no sandbox option at all, the number that confine both filesystem and network by default with central enforcement (score~3) is \dimABThreeTwo{}, and \dimABZeroThree{} have no egress control. Managed runtimes score higher (tier C/D means \dimCMeanTwo{} and \dimCMeanThree{}), because the provider runs each session in an isolated container or microVM. Where sandboxes exist, the incident record shows that their boundaries are often the weak point: symlink and working-directory tricks, writes to \texttt{.git} hooks and fallbacks to unsandboxed execution account for \nIncTSeventeen{} escape incidents (Section~\ref{sec:incidents}).

\paragraph*{Workspace trust (D04)} \dimABZeroFour{} tier A/B products honour repository configuration with no trust concept, and none reaches score~3. A frequent design choice is that headless mode bypasses the trust gate: Claude Code documents that \texttt{claude -p} in a never-trusted folder runs project hooks and MCP servers\evD~\cite{cc_permissions_trust}, which we observed\evT{}, whereas Grok Build ran an untrusted repository hook only after \texttt{--trust}\evD\evT{} and Copilot CLI did not start a repository MCP server in an untrusted folder\evT{}, not re-tested in a trusted folder (Section~\ref{sec:claims}). Similarly, Cline documents that project plugins in \texttt{.cline/plugins/} load when working in that repository\evD~\cite{cline_plugins}. These are documented design properties, not vulnerabilities, but a CI job running a harness on a pull request inherits them.

\paragraph*{Other dimensions} On D07 only \dimABTwoPlusSeven{} of \nRankedAB{} tier A/B products reach score~2, mostly because transcript retention is undocumented even where credentials sit in a 0600 file or keychain\evD{} (D07 column). Telemetry (D12) is scored on transparency and opt-out, not as a defect. D13 is examined in Section~\ref{sec:eval-supply}. SDK runtimes leave approvals, sandboxing and egress to the application; the rubric scores these as not provided (\emph{application responsibility}), so teams building on an SDK inherit those gaps unless they close them.
