\section{Reproducibility}\label{app:repro}
The repository contains the toolkit, rule pack, harness profiles, evidence ledger, matrix evidence, results JSON and this paper. Three entry points rebuild everything.
\begin{itemize}
\item \texttt{make all} runs the linter, type checker and tests with coverage, builds the documentation, regenerates every results-derived table, figure and number offline from committed data (\texttt{make experiments}, which ends with \texttt{experiments/paper\_numbers.py} writing \texttt{paper/numbers.tex}), and builds this paper with \texttt{paper/build.sh}.
\item \texttt{make bench} builds the pinned harness images (\texttt{make bench-images}), runs or resumes the canary grid against a local Ollama container, and re-runs the E3 analysis. It requires Docker and a GPU-backed Ollama container on the bench network; no vendor credentials are used.
\item \texttt{paper/build.sh} uses a pinned Tectonic release, downloaded with a SHA-256 check, and also writes the Markdown mirror \texttt{paper/paper.md} and the web version in \texttt{docs/paper/}.
\end{itemize}
Pinned versions: harness versions are listed in \texttt{VERSIONS.md}; bench images are tagged with the harness version (Table~\ref{tab:bench-catalogue}); the model server is Ollama~0.40.4, pinned by image digest; and Python dependencies are locked in \texttt{uv.lock}. Every reported number in the prose is a macro generated from \texttt{experiments/results/*.json}; design constants (versions, caps, mode bits, and the counts of classes and controls) are typed by hand.

\section{Review and Corrections}\label{app:corrections}
Following an internal hostile review we made these changes, all reflected in the results files and logged in the assumptions log: (1)~deterministic incident de-duplication, which removed one double-counted incident, with the excluded out-of-period row now shown; (2)~``patch latency'' recomputed from dates and reframed as fix date relative to advisory publication, with undated fixes reported; (3)~the E3 secret metric split into \emph{secret read} and \emph{secret in state} once the lenient metric was found to count harness persistence (Codex environment snapshots, the Claude Code \texttt{@path} import); (4)~E2 prevalence reported per stratum rather than pooled; (5)~matrix evidence labels aligned with the ledger, so that source reads are \evD{}, not \evT{}; (6)~one Grok Build fact obtained by listing strings in the shipped binary withdrawn as outside our metadata-only rule; (7)~claims about RQ3 shares, mode safety, claim coverage and rater independence reworded.

\section{Scorecard Rubric}\label{app:rubric}
The fifteen core dimensions, the 0--3 scale and the scoring rules are set out in Section~\ref{sec:controls}; a proposed D16 (local service and control-plane exposure) is excluded from all means until it has sufficient evidence. Each dimension poses a single question, for example D01, ``does the harness ask before risky tool actions, and can the approve-everything path be restricted?'', and D04, ``is repository-supplied configuration ignored until the user consents?''. The criteria are written so that they can be decided from labelled facts: score~3 always requires a safe default \emph{and} central enforceability (for D02, filesystem and network confined by default, not weakenable by the agent or by repository files, and enforceable by an administrator). The full criteria are in \texttt{matrix/rubric.md} (summary table: \texttt{paper/tables/rubric.md}), the scores with means and minima in \texttt{paper/tables/scorecard.tex}, and every cell's evidence and rationale in \texttt{matrix/}.
