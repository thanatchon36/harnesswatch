## Per runtime

### openai-agents-sdk
- Tracing default ON, exported to `https://api.openai.com/v1/traces/ingest` (Bearer key, `OpenAI-Beta: traces=v1`), `trace_include_sensitive_data` defaults true (tool args/outputs, generations). Opt-out: `OPENAI_AGENTS_DISABLE_TRACING=1`, `set_tracing_disabled(True)`, `RunConfig(tracing_disabled=True)`. Disabled tracing still flushes already-buffered data (docs). Not available under ZDR.
- Approvals: `needs_approval` False by default on function/shell tools; MCP `require_approval` default None. Guardrails: input guardrail runs in parallel with the agent by default (agent/tools can run before tripwire).
- Sandbox: `UnixLocalSandboxClient` has no confinement on Linux, partial (sandbox-exec FS only) on macOS. Docker + hosted clients (e2b, modal, daytona, cloudflare, vercel, runloop, blaxel).
- No GHSAs. SECURITY.md routes to OpenAI CVD.

### google-adk
- CVE-2026-4810 (critical, unauthenticated RCE in ADK server component incl. Cloud Run/GKE; fixed 1.28.1, 2.0.0a2). Redeploy required.
- `UnsafeLocalCodeExecutor` runs generated code via `exec` in a host child interpreter; safer: `ContainerCodeExecutor`, GKE, Vertex, Agent Engine sandbox.
- `BashToolPolicy.allowed_command_prefixes` defaults `("*",)`. Confirmation via `require_confirmation` (default False) on FunctionTool/McpToolset.
- `adk web`/api_server host default 127.0.0.1.
- No root SECURITY.md (404) - unverified whether org-level policy applies.

### microsoft-agent-framework
- Plain tools: `approval_mode` default `never_require`. Harness agent: approval ON by default with "don't ask again" standing rules (`tool` / `tool_with_arguments` scopes) and heuristic auto-approval.
- Experimental FIDES information-flow control in core/security.py; Hyperlight CodeAct bypasses it for nested tool calls (documented).
- Three GHSAs on 2026-10-07, all MCP-related (approval TOCTOU on headers, sensitive values to external MCP, Azure bearer token to wrong origin).
- Telemetry: UA string telemetry opt-out `AGENT_FRAMEWORK_USER_AGENT_DISABLED`; `ENABLE_SENSITIVE_DATA` gates content in OTel.

### langgraph
- No tool-approval layer; HITL via `interrupt()`. Checkpoint serde `JsonPlusSerializer` permissive msgpack by default (warning) unless `LANGGRAPH_STRICT_MSGPACK=true`; pickle fallback off by default; history of 4+ deserialization RCE advisories plus SQLi in SQLite store and several auth/multi-tenant flaws (see incidents).
- No root SECURITY.md; `.github/THREAT_MODEL.md` exists (not read in depth).

### deepagents / dcode
- SDK: `create_deep_agent(interrupt_on=..., permissions=[FilesystemPermission...], backend=...)`; FilesystemBackend `virtual_mode` is not a sandbox; LocalShellBackend unisolated.
- dcode: trusts cwd; project hooks (`.deepagents/hooks.json`) load only after workspace trust (headless: `--trust-project-hooks`); project `.mcp.json` requires approval (state `~/.deepagents/.state/mcp_trust.json`, bypass env `DEEPAGENTS_CODE_DANGEROUSLY_ENABLE_PROJECT_MCP_SERVERS`); AGENTS.md etc. read before approval. Non-interactive mode runs non-shell tools unattended; shell allow-list matches only first token (interpreter bypass, self-documented T13). Managed policy via `managed_config.toml`.
- GHSA-459r-276m-w72x deepagents-acp approval bypass (fixed 0.0.13, 2026-10-12).

### strands-agents
- `create_harness()` default tools: shell, read, write, edit, web_fetch, web_search, programmatic_tool_caller, subagent; `interventions` default None = every call runs. Presets `ask`/`smart`, Cedar policies.
- Default sandbox `NotASandboxLocalEnvironment` (host). Session dirs: harness `./.agent/sessions`; SDK FileSessionManager formerly `/tmp/strands/sessions` (GHSA-3w55 symlink LPE, GHSA-763v world-readable; fixed 1.48.0, 2026-07-17, advisories published 2026-10-05).
- Tracing off unless `OTEL_TRACES_EXPORTER` set.

## 1. pydantic-ai 2.56.0 (MIT)
- Packages: `pydantic-ai`, `pydantic-ai-slim`, `clai` (CLI, also `pai`), and the separate 0.x `pydantic-ai-harness` (Shell, Memory, BubblewrapSandbox, ApprovalReviewer, guardrails, subagents). The monorepo dir `src/pydantic_ai_harness` ships it.
- HITL: `requires_approval=True`, `ApprovalRequired`, `ApprovalRequiredToolset` -> `DeferredToolRequests`; resolved by caller (stop-and-resume) or inline `HandleDeferredToolCalls`. `approve_all=True` exists. Nothing is gated by default because core ships no shell/file tools.
- Execution: `LocalWorkspace` runs on the host as the user. `Shell` has a destructive-command denylist by default (`rm`, `dd`, `mkfs`, ...) but the docs state allowlists are best-effort (first token only; `python`, `git`, `make` escape). Real isolation = BubblewrapSandbox (no network by default, seccomp) or Modal/E2B/Sprites.
- MCP: `--mcp-config` / `load_mcp_servers()` read `{"mcpServers": {...}}`. Unknown keys incl. `disabled` and `type` are ignored (a server marked disabled still starts). `${VAR}` expands against the whole env. Docs warn the file is trusted input.
- Telemetry: none unless Logfire/OTel is configured and instrumentation enabled. `include_content=False` leaked content until 2.27.1/2.44.0 (GHSA-3gh4-cghq-f8v4, GHSA-4x9p-g9wm-8q7f).
- Advisories: 17 GHSAs (see incidents.d/G5b.csv). Pattern worth encoding: five SSRF-blocklist bypass advisories (IPv4-mapped, NAT64, zone-id, hostname normalisation), two `clai web` local-endpoint advisories (cross-site run trigger CVE-2026-107295 high; DNS rebinding CVE-2026-107292), UI-adapter trust of client-supplied message history / file references (CVE-2026-65975, CVE-2026-54249).
- MISSION.md: no seed path applies; there is no `~/.pydantic*` config dir.

## 1. claude-agent-sdk (Python 0.2.167, TypeScript 0.3.300)
Architecture (verified-by-test = read source): the SDK is a thin control-protocol wrapper that spawns the bundled `claude` CLI
(`_cli_version.py` = 2.1.300) as a subprocess with the caller's full environment. Permission decisions are made inside the CLI;
the SDK forwards `can_use_tool` requests over stdio (`_internal/query.py`: no callback registered -> raises "canUseTool callback is not provided").
Key facts
- `setting_sources=None` => no `--setting-sources` flag => CLI loads user + project + local settings (types.py docstring: "matches CLI defaults").
  So `.claude/settings.json` (permissions.allow, hooks) and `.claude/settings.local.json` in the working dir are honoured by default in SDK sessions (T02). `setting_sources=[]` = isolation mode.
  The `skills` option sets `["user","project"]` only when skills are enabled and sources unset.
- `permission_mode` values: default, acceptEdits, plan, bypassPermissions, dontAsk, auto. Unset mode => settings `permissions.defaultMode` else built-in default, which the docs say "can be auto mode"; before TS SDK v0.3.286 unset == `default`. Python docs page gives the same ladder.
- Evaluation order (docs): hooks -> deny -> ask -> mode -> allow -> `canUseTool`. `allowed_tools` does not restrict; a bare entry (`"Read"`) auto-approves the whole tool and skips the callback. `allowed_tools=["Read"]` + `bypassPermissions` still approves Bash/Write/Edit. Python emits `CanUseToolShadowedWarning` (TS: process warning `CLAUDE_SDK_CAN_USE_TOOL_SHADOWED`).
- Sandbox: `ClaudeAgentOptions.sandbox` merged into `--settings` JSON; `SandboxSettings.enabled` default False, `allowUnsandboxedCommands` default True, `autoAllowBashIfSandboxed` default True.
- Subagents run in the parent's mode; `bypassPermissions` on an AgentDefinition is never applied unless the parent is in bypass (CLI >= 2.1.267).
- Windows: `.bat/.cmd` CLI shims (npm `claude.cmd`) refused (BatBadBut class); `resume`/`session_id` reject cmd metacharacters.
- Licensing is ambiguous: Python repo has an MIT LICENSE, README says Commercial Terms; TS repo LICENSE.md is "All rights reserved"; bundled CLI is closed. Recorded `open_source: true` for the Python source only.
Incident: GHSA-h4mw-j7qp-8mwm / CVE-2026-96620 (critical, CVSS v4 9.2): `resume` value starting with `-` passed as separate argv token lets an attacker inject `--mcp-config` (stdio MCP server => command execution at CLI start, bypassing SDK permission controls). Affected < 0.2.121, patched 0.2.121 (release 2026-07-17), advisory published 2026-09-12. Current code passes `--resume=<id>` / `--session-id=<id>`. CVE not in NVD at access time (query returned 0 results). Related hardening in CHANGELOG: skill names validated against `--allowedTools` injection (#1145); Windows cmd.exe handling (#1127); build-script injection via CLAUDE_CLI_VERSION (#1117); `mcp>=1.23.0` bump for CVE-2025-66416 (#927).
No advisories returned for the TS repo via API; no SECURITY.md at python repo root (404).
Not verified: whether the interactive workspace-trust dialog applies in SDK mode; whether `.mcp.json` project servers need approval in SDK mode; telemetry/retention (CLI/API-plan property).

## Cross-cutting findings
1. Defaults diverge on the same question "does the agent run unattended?": Managed Agents builtin toolset = always_allow (but isolated container), AgentCore harness = all tools incl. shell enabled, OpenAI MCP = approval required, Agent SDK = depends on CLI settings (may start in auto mode).
