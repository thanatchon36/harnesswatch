## Root-cause patterns
1. **Pre-consent execution of repo content (RC2/T02)**: Claude Code trust-dialog bugs (59536, 65099, ph6w, 59041), Codex project-local config (61260), Zed project settings/LSP/MCP (55012, 68432/3), Cursor .code-workspace, CLI config and MCP config (61590, 61592, 64109), Roo `.vscode/settings.json`/.code-workspace, Cursor Workspace Trust off (Oasis). Dominant class.
2. **Self-modification of the agent's own config via prompt injection**: write `chat.tools.autoApprove` (53773), create `.cursor/mcp.json` (54135), `.vscode/settings.json` (Roo 53536), multi-root workspace (64660). The permission model treats workspace files as ordinary writes.
3. **Allowlist/validator bypasses (RC3/T03)**: shell-parsing flaws in Claude Code (echo, rg, sed, generic validator), Roo (newline, parameter expansion, zsh), Gemini CLI (root-command only), Cursor allow-list and case/NTFS/backslash path quirks, symlink and prefix-match path checks (Claude 54794, 59829; Roo 58373; Filesystem MCP 53109/53110). Same bug class repeats across vendors.
4. **Exfil channels that need no approval (T08/RC9)**: DNS via ping/nslookup (Claude 55284, Cline), Mermaid/image fetch (Cursor 54132, 61589), JSON schema fetch (Cursor 49150, Roo 53097), Camo proxy (CamoLeak), browser allowlist with webhook.site (Antigravity).
5. **Unauthenticated local services (RC4)**: Inspector proxy (49596), IDE WebSocket (52882), AgentAPI, MCP SDK DNS rebinding defaults (66414/66416).
6. **MCP trust model (T04)**: rug pull after approval (54136), tool poisoning, deeplink install without args, mcp-remote untrusted server -> RCE (6514), toxic agent flows needing no code bug (GitHub/Supabase MCP).
7. **Supply chain**: CI token theft (Nx, Amazon Q) turning into harness-weaponisation (s1ngularity passed `--dangerously-skip-permissions`, `--yolo`, `--trust-all-tools`).
8. **Silent fixes / late advisories**: many advisories (Claude 65099, 66032; Roo; mcp-server-git 68143) were published months after the fix shipped. Disclosure-basis latency is therefore negative for those rows.

## Latency method and caveats
- patch_latency_days = fix_date - report date when a report date is published; otherwise vs GHSA/disclosure date (negative: fix before advisory). Report date only known for: Codex 61260 (13), MCPoison (13), Gemini CLI (28), Copilot 53773 (44), Inspector 49596 (79 from earliest report). Treat the other numbers as "advisory lag", not response time.
- fix_date for npm/PyPI/GitHub-release-based rows = package publish timestamp of the fixed version. Blank where the fixed version's date could not be fetched (e.g. Cursor 1.3.9, Claude 0.2.111, 2025.09.17 CLI build).
- GHSA `published_at` used as date_disclosed for GHSA rows; NVD publication often 0 to 3 days later.
- taxonomy/root-cause labels are my judgment from advisory titles; a few advisory summaries are truncated (e.g. GHSA-2jjv-qf24-vfm4).
