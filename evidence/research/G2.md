## 1. Cline (Tier A, analysed)
Architecture: three surfaces share `@cline/core`: VS Code extension (4.1.24), CLI `cline` (3.0.71, Bun-built platform binaries on npm), desktop app; local "hub" daemon (`cline hub`, dashboard 127.0.0.1:8787) and separate `kanban` npm package (127.0.0.1:3484).
Permission path: CLI builds `toolPolicies {"*": {autoApprove: effectiveToolAutoApprove}}`; `defaultToolAutoApprove = true` (apps/cli/src/main.ts:885); persisted override `toolAutoApprove` in `~/.cline/data/settings/global-settings.json`; `--yolo`/`--auto-approve true|false`. ACP mode refuses default and needs explicit `--auto-approve true`. VS Code: `autoApprovalSettings.actions.*`; the old `yoloModeToggled` is migrated into all-true actions. Command safety is the model's `requires_approval` flag (no allowlist) -> Mindgard DNS/`ping` exfil.
Config loading: hooks (`.clinerules/hooks`, `.cline/hooks`), plugins (`.cline/plugins`), skills (`.cline|.claude|.agents/skills`), rules (`.clinerules`, `.cline/rules`) are discovered from the workspace; no trust prompt found in CLI source (grep "trust"). MCP is user-level only (no project MCP file), but the hub dashboard advisory shows MCP entries can be injected via a local WebSocket.
Secrets: providers.json 0600/0700 plaintext; MCP env/headers plaintext.
Supply chain: GHSA-9ppg-jx86-fqw7 (cline@2.3.0, 2026-02-17); remediation = OIDC provenance (cli-publish.yml sets NPM_CONFIG_PROVENANCE).
Enterprise: hosted remote config (rules/providers/MCP/telemetry/`yoloModeAllowed`); docs table lists "Allow YOLO mode" as unsupported in all three products while a dedicated page documents it -> inconsistent docs (open question).
Bench: `cline --yolo --json "<task>" ` with provider `openai-compatible`/`ollama` (not run). Config isolation via `--config DIR --data-dir DIR` or `CLINE_DIR`.

Risky vs safe fixtures:
```json
// risky: ~/.cline/data/settings/global-settings.json
{ "toolAutoApprove": true }
// safe
{ "toolAutoApprove": false, "telemetryOptOut": true }
// risky: cline_mcp_settings.json (unpinned launcher + blanket tool approval + plaintext secret)
{ "mcpServers": { "x": { "command": "npx", "args": ["-y", "some-mcp"], "env": {"API_KEY": "sk-..."}, "autoApprove": ["*"] } } }
// safe
{ "mcpServers": { "x": { "command": "node", "args": ["/opt/mcp/x/server.js"], "autoApprove": [] } } }
// remote default-transport trap: no "type" => legacy sse
{ "mcpServers": { "r": { "url": "https://example.com/mcp" } } }
```
CLI invocation to flag in CI workflows: `cline --yolo`, `cline --auto-approve true`, `cline --autoapprove`, bare `cline "prompt"` (default approve!).

## 2. Roo Code (Tier A, analysed; DISCONTINUED)
Archived repo; last release v3.54.0. Still relevant historically: 11 GHSAs (CVE-2025-53097 .. 65946) = five of them allowlist/command-validation bypasses, three config-file auto-write RCEs (`.roo/mcp.json`, `.vscode/settings.json`, `.code-workspace`), one workflow injection, one symlink bypass of `.rooignore`.
Permission keys (VS Code state, `packages/types/src/global-settings.ts`): `autoApprovalEnabled`, `alwaysAllowReadOnly[OutsideWorkspace]`, `alwaysAllowWrite[OutsideWorkspace|Protected]`, `alwaysAllowExecute`, `alwaysAllowMcp`, `alwaysAllowModeSwitch`, `alwaysAllowSubtasks`; VS Code settings `roo-cline.allowedCommands` (default `["git log","git diff","git show"]`), `roo-cline.deniedCommands`. MCP per-server `alwaysAllow: ["*"]` wildcard. Protected-write list requires separate opt-in (.roo/**, .vscode/**, .roomodes, .roorules*, AGENTS.md).
CLI (`@roo-code/cli` 0.1.17, curl|sh installer): auto-approves by default, `-a` to require approval, `--print`, only 5 providers, **no base-URL flag** -> not usable for local Ollama bench; recommend excluding Roo from canary bench or using the Zoo-Code fork (not analysed).

## 3. Kilo Code (Tier A, analysed)
v7.8.10 = OpenCode-derived. Config precedence: managed (`/etc/kilo`, `/Library/Application Support/kilo`, `%ProgramData%\kilo`, MDM plist `ai.opencode.managed`) over project over global; project config parsed as untrusted for `{env:}`/`{file:}`. `KILO_DISABLE_PROJECT_CONFIG=1` kills project config. Permissions: `permission` map, last-match-wins globs; base ruleset `"*": "allow"` + bash default `ask` with allowlist (includes `printenv`, `cp`, `mv`, `touch`, `mkdir`, `tar`); `.env` reads ask. `kilo run` without `--auto` auto-rejects and exits 1 (good CI default). Sandbox bubblewrap/Seatbelt opt-in (`sandbox.enabled`), project cannot weaken. No folder-trust prompt; plugins (`plugin` key, `.kilo/plugins`) and project `mcp` entries load. Org MCP allowlist is a design proposal only. SECURITY.md states "does not sandbox".
CVEs found only via NVD (VulDB): CVE-2026-8765 (path traversal in file-diff API, <=7.0.47), CVE-2025-11445 (legacy v4). No GHSAs.
Bench: `kilo run --auto "..."` with `kilo.json` `{"model":"ollama/<m>","provider":{"ollama":{"baseURL":"http://hw-ollama:11434/v1"}}}` (from docs, not run).

## 4. Continue (Tier A, analysed; UNMAINTAINED)
`cn` (npm 1.5.47). Permissions `allow|ask|exclude`; defaults read tools allow, Edit/Write/Bash ask; headless excludes ask tools; `--auto` = allow everything and overrides all other sources; `--allow "*"`. `permissions.yaml` in `~/.continue`. Hooks are Claude-Code compatible and loaded from `.continue/settings.json`, `.continue/settings.local.json`, `.claude/settings*.json` of the project and home (so a repo's Claude Code hooks also run under `cn`). `<workspace>/.continue/.env` and `.env` feed secret resolution. MCP via `mcpServers` YAML **list** in config.yaml or `.continue/mcpServers/*.yaml|json`. Telemetry removed in 2.0.0. Local models: `models: [{provider: ollama, model, apiBase}]` + `cn --config file`. No advisories, no CVEs found. One item is recorded privately pending coordinated disclosure.

## 5. Aider (Tier A, analysed)
Python; no sandbox, no hooks, no MCP, no SECURITY.md/advisories. Config: `.aider.conf.yml` searched in home, git root, cwd; `.env` same (override=True) plus `~/.aider/oauth-keys.env`. YAML keys = long flag names (`yes-always`, `auto-commits`, `test-cmd`, `auto-test`, `lint-cmd`, `openai-api-base`, `analytics-posthog-host`, `load`, `set-env`); env prefix `AIDER_`. A cloned repo can therefore repoint the API base (key exfil to attacker host), auto-run `test-cmd`, or execute a `load` command script - documented behaviour but no trust prompt. `--yes-always` does NOT auto-run LLM-suggested shell commands (explicit_yes_required) - verified in io.py/base_coder.py - but auto-adds URLs/files and runs fix loops. Defaults: auto-commits on, dirty-commits on, history in repo (`.aider.chat.history.md`, `.aider.input.history`, `.aider.llm.history`). Analytics: opt-in prompt for 10% sample (analytics.py).
Bench: `OLLAMA_API_BASE=http://hw-ollama:11434 aider --model ollama_chat/<m> --message "..." --yes-always --no-auto-commits --no-analytics --no-check-update --exit` (docs; not run).

## 6. OpenHands (Tier A, analysed; v1 architecture)
Components: Agent Canvas (npm `@openhands/agent-canvas`, Docker image), agent-server + SDK (`software-agent-sdk`), legacy CLI (unmaintained). Quickstart "Option 1: Without a Sandbox" runs host-level agent; Docker options exist. Agent-server auth = `session_api_keys` (empty => unsecured; Canvas public mode uses `LOCAL_BACKEND_API_KEY`); CORS allows localhost + configured origins. Confirmation: `AlwaysConfirm` (TUI default) / `NeverConfirm` (headless, `--yolo`, `--always-approve`) / `ConfirmRisky` + LLM analyzer (`--llm-approve`). Project `.openhands/hooks.json` hooks (command|prompt|agent) load on start; skills/plugins from `.agents/`, `.openhands/`; skill/plugin dirs can ship `.mcp.json`. Memory: `.openhands/memory/MEMORY.md` + user-level. CLI persists LLM key in `~/.openhands/agent_settings.json` (expose_secrets=True). Env LLM_* ignored unless `--override-with-envs`. CVEs: CVE-2026-33718 (git diff command injection, <=1.4.0, fixed 1.5.0), CVE-2026-19022 (legacy resolver; NVD, vendor deleted issue).
Fixtures:

## 7. goose (Tier A, analysed)
Rust. Default `GOOSE_MODE=auto` (autonomous; docs warn). Modes via config key or env; per-tool lists in `permission.yaml`. Extensions in `config.yaml` (`extensions:` map; types builtin/platform/stdio/streamable_http; stdio fields `cmd,args,envs,env_keys`; remote `uri,headers`). `GOOSE_ALLOWLIST` URL restricts installs; stdio extension launches are checked against OSV `MAL-*`. Prompt-injection detector off by default (`SECURITY_PROMPT_ENABLED`). Keyring by default, plaintext `secrets.yaml` fallback; telemetry opt-in. `.goosehints` and `AGENTS.md` loaded from cwd hierarchy. CVE-2026-72718 (`goose review` -> git `core.fsmonitor`, <1.44.0). Recipes carry `extensions` blocks.
Bench: `GOOSE_PROVIDER=ollama GOOSE_MODEL=<m> OLLAMA_HOST=hw-ollama:11434 GOOSE_MODE=auto goose run --no-session -q -t "..."` (docs; OLLAMA_HOST format incl. scheme unverified).

## 8. Warp (Tier A open-core, analysed client only)
AGPL client + MIT UI crates. Agent permissions are execution profiles (per category) with regex allow/deny lists; GUI default asks for commands; **the non-interactive CLI profile `Default (CLI)` is AlwaysAllow for everything** with the denylist as only guard (empty when sandboxed). `auto_approve_bypasses_command_denylist` defaults **true**. Docs (denylist = wget,curl,rm,eval) are stale versus source (18 regexes). Source default allowlist constant (cat, echo, find, grep, ls, which) is applied to the CLI profile; `find .*` allowlisting is notable. Ten GHSAs/CVEs published 2026-06-09, fixes in stable builds 2026-05-06/13 (denylist bypass via env-var prefixes, Grep/FileGlob injection, OSC 52 clipboard, SSH, WSL link, etc.). MCP: native `.warp/.mcp.json` (project) and `~/.warp/.mcp.json` always spawned; Claude/Codex/.agents configs only if `agents.mcp_servers.file_based_mcp_enabled` (default false). Custom endpoints are proxied via Warp's server, so localhost Ollama is not reachable; headless needs a Warp account/`WARP_API_KEY` -> mark bench cell N/A (no access / architecture). No GitHub release after June 2026 found.
