# B4: access paths for the other closed Tier-B harnesses

Access date 2026-10-15. Docs, changelogs and npm registry metadata only. Nothing was installed or run on the host. No logins, no decompiling.
npm metadata came from `docker run --rm node:22-slim npm view <pkg> --json`, run in a throwaway container.
Files: `evidence/ledger.d/B4.csv`, `matrix/claims_vs_observed.d/B4.csv`, `evidence/sources_B4.bib`.

**Question.** Can the harness run headless in a Linux container with no vendor account, against a custom or local OpenAI- or Anthropic-compatible endpoint (Ollama)?

## Counts
- Verified no-login local-model path (official docs state it outright): **1 closed harness** (Copilot CLI), plus **trae-agent** (MIT, open source).
- Docs strongly imply a path, but a container check is needed: **1** (Junie CLI).
- BYOK exists but login is still required: **2** (Factory Droid public build, Qoder).
- No path: **6** (Cursor CLI, Kiro CLI, Amp, Auggie, Jules, Windsurf/Devin Desktop).
- Bench candidates from B4: Copilot CLI (`copilot -p` + `COPILOT_OFFLINE=true`), Junie (if the container check passes), trae-agent.

## Caveats
- Ollama path for Copilot: the docs example is `http://localhost:11434` with no `/v1`. Inside the bench the host is the `hw-ollama` container, not localhost. Copilot's 128k context recommendation conflicts with A15's small-model choice. Expect weak task completion, so record it as a result, not a skip.
- Supply chain: none of the 8 npm packages checked (including `@ampcode/cli`) carries a provenance attestation. Each has standard registry signatures. Five run a postinstall script (droid, junie, qodercli, jules, @ampcode/cli). Copilot and Auggie do not.
- ToS: I found no explicit clause on automated or benchmark use in the pages read. The vendor terms were not read in full.
- No new vulnerability was suspected, so nothing was added to `private/DISCLOSURE_DRAFT.md`. Junie's headless auto-trust is a documented design choice, not a bug.
