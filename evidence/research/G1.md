## Cross-cutting summary (security-relevant)
1. Only Codex ships OS sandboxing + network-off + approval policy ON by default; Claude Code and Gemini CLI ship sandboxes but off; OpenCode, Crush have none; Qwen Code has an opt-in Linux sandbox.
2. Repo-level config as code execution (T02): OpenCode (no trust gate, declared out of scope) and Crush (project `crushrc` is a full Bash script executed at config load; documented as "trusted code") load repo config with no consent. Qwen Code has folder trust but OFF by default. Claude Code, Codex, Gemini CLI gate on trust (all three had CVEs for pre-trust execution).
3. Headless/CI is the weak spot: `claude -p` never shows the trust dialog and runs repo hooks / `.mcp.json` servers; `crush run` auto-approves everything; `opencode run --auto/--yolo`; Gemini CLI headless was auto-trusting until 0.39.1 (CVE-2026-12537, CVSS 10).
4. MISSION seed details are stale in several places (below).
5. Anthropic-compatible local endpoint exists: Ollama `/v1/messages` (docs.ollama.com) so Claude Code can be benchmarked with `ANTHROPIC_BASE_URL=http://<ollama>:11434 ANTHROPIC_AUTH_TOKEN=ollama`.

## claude-code (Tier B, treated as fully analysed)
Architecture: Node/Bun-bundled agent loop, tool layer (Bash, Edit, Write, WebFetch, MCP, Agent), permission engine (deny > ask > allow, mode on top), optional OS sandbox for Bash only (Seatbelt/bubblewrap), hooks (33 events, 5 handler types), plugins/marketplaces, subagents, auto memory. Settings hierarchy (docs): managed (`/etc/claude-code/managed-settings.json` + `managed-settings.d/*.json`; macOS `/Library/Application Support/ClaudeCode/`; Windows `C:\Program Files\ClaudeCode\`; MDM; server-managed) > `--settings` > `.claude/settings.local.json` > `.claude/settings.json` > `~/.claude/settings.json`. `permissions.defaultMode` values: default, acceptEdits, plan, auto, dontAsk, bypassPermissions, manual(alias). `auto` and `bypassPermissions` ignored from project/local files (bypass since v2.1.257); `permissions.disableBypassPermissionsMode: "disable"` blocks the flag.
Trust: interactive sessions hold ALL settings hooks until workspace trust is accepted; `claude -p`/SDK never prompt and treat the folder as trusted for hooks, `env`, `apiKeyHelper`, `.mcp.json` (connected without asking); repo `permissions.allow` is ignored untrusted. Mitigations (docs): `--bare`, `--setting-sources user`, `--settings '{"disableAllHooks":true}'`, `disabledMcpjsonServers`.
MCP: `.mcp.json` (project), `~/.claude.json` (`mcpServers` user, `projects.<path>.mcpServers` local), `--mcp-config`, `managed-mcp.json`; entry `type` stdio|http|sse|ws; entry with `url` and no `type` is an error. Approval keys `enabledMcpjsonServers` / `enableAllProjectMcpServers` / `disabledMcpjsonServers`; ignored from committed project settings in untrusted folders.
Telemetry: usage metrics + error reporting default ON; `DISABLE_TELEMETRY`, `DISABLE_ERROR_REPORTING`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`; OTel opt-in `CLAUDE_CODE_ENABLE_TELEMETRY=1`.
Local install (2.1.300, Linux): `~/.claude/.credentials.json` mode 0600 (verified); `~/.claude/settings.json` keys: permissions, statusLine, enabledPlugins, extraKnownMarketplaces, skipDangerousModePermissionPrompt, theme (note: the user has accepted the bypass dialog); `~/.claude.json` mode 0600; dirs: projects, plugins, skills, sessions, shell-snapshots, file-history, paste-cache, backups.
Local model: Ollama docs state `/v1/messages` Anthropic compatibility (Claude Code named); no count_tokens; setting a non-first-party `ANTHROPIC_BASE_URL` disables MCP tool search (set `ENABLE_TOOL_SEARCH=true`) and Remote Control. Small local models reported impractical by third parties; not tested.
Advisories: 35 GHSAs in anthropics/claude-code (several are Claude Desktop/Cowork). Recurring classes: command-validation bypass (sed/find/rg/echo/git email), trust-dialog bypasses (pre-trust exec, worktree spoofing, repo-controlled settings), sandbox escapes (symlink, worktree path confusion, settings.json injection), plugin SHA-pin bypass (2.1.179, 2026-10-09), WebFetch preapproved domain exfil (CVE-2026-54316).

B1 addendum (2026-10-15): corrections, with details in `evidence/ledger.d/B1.csv` and the observe plan in `evidence/research/B1_observe_plan.md`.
(1) The built-in starting permission mode is now `auto`: interactive sessions on >=2.1.283, and `-p` without feature flags on >=2.1.285. Before this addendum the profile said `default`.
(2) Error reports are sent only for Pro/Max sign-ins on >=2.1.198, so they are not default-on for everyone. Documented telemetry hosts are api.anthropic.com and two Datadog intake hosts; the docs list no Statsig or Sentry host.
(3) The WebFetch hostname preflight to api.anthropic.com runs on every provider and is not covered by CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC.
(4) npm 2.1.300 is published through npm trusted publishing (GitHub OIDC) with registry signatures but has no provenance attestation. It has a postinstall `node install.cjs`, and Linux binaries are not individually code-signed.
(5) Under `-p`, a project `.mcp.json` headersHelper and project subagent frontmatter hooks are not run, while settings hooks, `env` and `.mcp.json` servers are.

## codex-cli (Tier A)
Architecture: Rust workspace (`codex-rs`: core, exec, tui, config, execpolicy, linux-sandbox/bwrap, network-proxy, hooks, memories, mcp, app-server). Config TOML layers: CLI `-c` > project `.codex/config.toml` (trusted only) > `--profile` file > `~/.codex/config.toml` > cloud-managed > `/etc/codex/config.toml`; admin `requirements.toml` (`/etc/codex/requirements.toml`, `%ProgramData%\OpenAI\Codex`, MDM) constrains values.
Permissions (source: protocol.rs AskForApproval): `on-request` (default), `never`, `granular{sandbox_approval,rules,skill_approval,request_permissions,mcp_elicitations}`; `untrusted` retired; `on-failure` alias. `sandbox_mode`: read-only | workspace-write | danger-full-access. Flags: `--yolo` / `--dangerously-bypass-approvals-and-sandbox`, `--approve-for-me` (alias `--not-so-yolo`), `--dangerously-bypass-hook-trust`, `--oss --local-provider ollama|lmstudio`. Protected paths in writable roots: `.git`, `.agents`, `.codex`, `.aws`.
Trust: `projects."<path>".trust_level = "trusted"|"untrusted"` in user config; untrusted/unknown projects ignore project config, hooks and rules; project config may not set providers/base URLs/notify/profile/otel; non-managed hooks need hash-based review.
Network: off by default; `[features.network_proxy]` domain allow/deny (deny wins); not applied to web search/MCP/connectors/model traffic; `web_search = "cached"` default.
Credentials: `cli_auth_credentials_store` file|keyring|auto|ephemeral; `~/.codex/auth.json`. Memories off by default (`~/.codex/memories`). Analytics on by default (`[analytics] enabled=false`). OTel opt-in.
Local model: `codex exec --oss --local-provider ollama -m MODEL` (built-in provider id `ollama`, Responses wire API only; `wire_api="chat"` removed) or `[model_providers.local_ollama] base_url="http://localhost:11434/v1"`. Needs Ollama's Responses endpoint (not tested).
CVEs: CVE-2025-59532 (sandbox cwd, fixed 0.39.0), CVE-2025-61260 (project .env/.codex/config.toml MCP exec, <=0.23.0; GHSA published 2026-04-14). Disclosure: Bugcrowd. Release signing: sigstore files for Linux artifacts; `openai/codex-action` defaults `safety-strategy: drop-sudo`.
Closed: Codex cloud/web/desktop - docs only.

### Linter fixtures (codex)
Risky: `approval_policy = "never"` + `sandbox_mode = "danger-full-access"`; `[sandbox_workspace_write]\nnetwork_access = true`; `[projects."/home/u/src"]\ntrust_level = "trusted"` combined with project `.codex/config.toml` containing `[mcp_servers.x] command = "sh"`; `web_search = "live"`; `[features.network_proxy.domains] "*" = "allow"`; CI step `codex exec --yolo "$PR_BODY"`; `approvals_reviewer="auto_review"` + `approval_policy="never"`.
Safe: `approval_policy="on-request"`, `sandbox_mode="workspace-write"`, network_access=false; `codex exec --sandbox read-only`.

## opencode (Tier A)
Architecture: TypeScript/Bun monorepo (packages/opencode core; Effect). Local HTTP server for TUI/web/SDK. Config JSONC precedence: remote `.well-known/opencode` < `~/.config/opencode/opencode.json` < `OPENCODE_CONFIG` < project `opencode.json` (walk up to worktree) < `.opencode/` < `OPENCODE_CONFIG_CONTENT` < managed `/etc/opencode` (or macOS/Windows equivalents) < macOS MDM plist. No project-trust prompt anywhere in the loader.
Permissions (agent.ts defaults): `"*":"allow"`, `doom_loop:ask`, `external_directory:ask`, `.env` reads `ask` (docs say deny), question/plan_* deny. Rules: allow|ask|deny, object patterns, last match wins; `OPENCODE_PERMISSION` env; `--auto/--yolo/--dangerously-skip-permissions` on `opencode run`. SECURITY.md: no sandbox, permission system is UX only, malicious config and MCP servers out of scope, AI-generated reports banned.
MCP: `mcp.<name>` local `{type:"local", command:[...], environment:{}, enabled}` / remote `{type:"remote", url, headers, oauth}`; no approval step. Plugins: npm packages auto-installed at startup via Bun; `.opencode/plugins/` auto-loaded code. Skills read from `.opencode/`, `.claude/`, `.agents/` (both project and global). Also reads `CLAUDE.md` and `~/.claude/CLAUDE.md` unless disabled.
Credentials: `~/.local/share/opencode/auth.json` (0600), `mcp-auth.json`; sessions in `opencode.db`. `share` default manual; `auto` publishes every conversation publicly.
Advisories: GHSA-vxw4-wv6m-9hhh/CVE-2026-22812 (unauth server RCE, fixed 1.0.216), GHSA-c83v-7274-4vgp/CVE-2026-22813 (web UI XSS -> /pty RCE, fixed 1.1.10), GHSA-632h-h47v-g4x4 (cross-site /global/upgrade installs arbitrary npm pkg, >=1.14.30 fixed 1.18.22, Datadog Security Labs write-up).
Local model: `provider.ollama` with `@ai-sdk/openai-compatible`, `options.baseURL` = `http://localhost:11434/v1`. Headless: `opencode run -m ollama/<model> --format json "..."`.
Installer: `curl -fsSL https://opencode.ai/install | bash` has no checksum/signature verification (read at v1.19.0).
Telemetry/retention: no documentation found (unverified).

### Linter fixtures (opencode)
Risky: `{"permission":"allow"}`; `{"permission":{"bash":"allow","external_directory":"allow"}}`; `{"mcp":{"x":{"type":"local","command":["npx","-y","pkg"],"enabled":true}}}` in a repo-committed `opencode.json`; `{"plugin":["some-pkg@latest"]}`; `{"share":"auto"}`; CI `opencode run --yolo`; `OPENCODE_SERVER_PASSWORD` unset with `opencode serve --hostname 0.0.0.0`.
Safe: `{"permission":{"*":"ask","bash":{"*":"ask","git status":"allow","rm *":"deny"},"read":{"*.env":"deny"}}}`.

## crush (Tier A, source-available)
Architecture: Go (Bubble Tea TUI), client/server split (`crush server`), embedded Bash-compatible shell interpreter used for bash tool, hooks and `crushrc`. Config lookup: `/etc/crush/crush.json`, user `crush.json` + `crushrc`, data-dir JSON, then project `.crushrc`, `crushrc`, `.crush.json`, `crush.json` up to git root. Permissions: prompt per tool; `permissions.allowed_tools`; `--yolo`; safe-command prefixes skip prompts for non-chained commands (open issue #2368 reports a safe-command bypass: third-party-report/unverified); `crush run` calls `AutoApproveSession`.
Key design weakness (vendor-documented, T02/RC2): project-level `crushrc` is executed as Bash at load, and `$(...)` inside `crush.json` runs at load, with no trust prompt; README: "Both crushrc and crush.json are trusted code ... Don't launch Crush in a directory whose config you haven't reviewed." Trust PR #3607 open. Not treated as a new vulnerability (public, documented). The ConfigBuilder timeout is 30 s; environment inherited (`os.Environ()`), so secrets in env are visible to a malicious crushrc.
MCP in `mcp` (stdio/http/sse, `disabled`, `enabled_tools`); skills from `.agents/.crush/.claude/.cursor/skills`; context files include `.cursorrules`, `CLAUDE.md`, `GEMINI.md`, `AGENTS.md`. Hooks: `PreToolUse` only. Telemetry on by default (`CRUSH_DISABLE_METRICS`, `DO_NOT_TRACK`). Releases: cosign `.sigstore.json`, checksums, SBOM. Disclosure: org SECURITY.md email; no advisories, no bounty. Ollama: provider type `ollama` base `http://localhost:11434/v1`.

### Linter fixtures (crush)
Risky: any committed `crushrc` or `.crushrc` (shell executes on load); `crush.json` containing `"$(`; `{"permissions":{"allowed_tools":["bash","edit","write"]}}`; CI `crush run` / `crush --yolo`; committed `hooks` entries in crush.json whose command is not in-repo.
Safe: `{"permissions":{"allowed_tools":["view","ls","grep"]}}` and no project-level crushrc.

## gemini-cli (Tier A)
Architecture: TypeScript monorepo (packages/cli, core, a2a-server, vscode-ide-companion). Settings merge: system (`/etc/gemini-cli/settings.json`) overrides, user `~/.gemini/settings.json`, workspace `.gemini/settings.json`. Approval modes: default | auto_edit | yolo | plan (`--approval-mode`, `--yolo`); `security.disableYoloMode`, `admin.secureModeEnabled`. Policy engine TOML (`~/.gemini/policies`, admin tier; workspace tier disabled). Folder trust default ON in code (docs stale), trust file `~/.gemini/trustedFolders.json`; headless needs `--skip-trust` or `GEMINI_CLI_TRUST_WORKSPACE=true` (CVE-2026-12537 fix, 0.39.1). Hooks fingerprinted per project.
MCP `mcpServers` entries (command,args,env,cwd,url,httpUrl,headers,tcp,type,timeout,trust,includeTools,excludeTools,oauth); `mcp.allowed/excluded`; `trust:true` skips confirmations. Sandbox opt-in: Seatbelt (permissive-open default allows network), Docker/Podman, runsc, lxc. Credentials `~/.gemini/oauth_creds.json`; chats `~/.gemini/tmp/<hash>/chats`. Telemetry: usage statistics default true; OTel opt-in. Memory: `save_memory` writes `~/.gemini/GEMINI.md`.
No local-model path: only Gemini wire format via `GOOGLE_GEMINI_BASE_URL`; canary bench would need a Gemini-API shim -> mark bench cell `N/A (no native local model support)` unless shim added.
Advisory: GHSA-wpqr-6v78-jr5g (critical, CVSS 10), duplicate GHSA-jj69-4grx-fqj5 for run-gemini-cli <0.1.22. Lifecycle: consumer end 2026-06-18, successor Antigravity CLI (`agy`, closed; Tier B in MISSION).

### Linter fixtures (gemini)

## qwen-code (Tier A)
Architecture: TypeScript monorepo (packages/cli, core, sdk-*, web-shell, desktop, channels, cua-driver, browser-use). Settings: system-defaults < user `~/.qwen/settings.json` < project `.qwen/settings.json` < system `/etc/qwen-code/settings.json`; some keys honoured only from operator scopes. Approval: `tools.approvalMode` plan|default|auto-edit|auto|yolo with schema default AUTO (LLM classifier); `permissions.allow/ask/deny` (deny wins). Folder trust defaults OFF in code (`?? false`) - repo `.qwen/settings.json`, `.env` and extensions load unless the user enables trust. Optional Linux execution sandbox (bwrap/Landlock) configured only in user/system settings. `qwen serve` HTTP daemon binds 127.0.0.1:4170 with no auth on loopback by default ("any local process ... code execution as the daemon user"; non-loopback requires bearer token).
Auth: Qwen OAuth free tier discontinued 2026-04-15; keys via `modelProviders` + `env` in settings.json (plaintext option). Local: `modelProviders.openai[]` baseUrl `http://localhost:11434/v1`, `OLLAMA_API_KEY=ollama`. Telemetry: usage statistics default true. Memory: auto + team memory (git-tracked `.qwen/team-memory/`, optional auto commit/push) + Mem0. Disclosure: Aliyun portal; no advisories. Gap: no per-server MCP approval; hooks can come from repo settings.

### Linter fixtures (qwen)
Risky: `{"tools":{"approvalMode":"yolo"}}` (or default `auto` unreviewed); `{"permissions":{"allow":["run_shell_command"]}}`; folder trust not enabled (`security.folderTrust.enabled` absent/false) plus committed `.qwen/settings.json` with `mcpServers`/`hooks`; plaintext `"env":{"DASHSCOPE_API_KEY":"sk-..."}` in settings.json; `qwen serve --host 0.0.0.0` without `--require-auth`.
