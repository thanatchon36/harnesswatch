## 1. What in MISSION.md was wrong / outdated

Config home is `~/.dsh` / `$DSH_HOME` (seed `~/.dsh/` correct) but config is **not** a single settings file: it is YAML plugin-patch layers `cordis.patch.yml` in `$DSH_HOME/profiles/<profile>/`. The `dsh` "headless profile" is `dsh --profile headless "<task>"`. Entry points: `dsh web`, `--profile acp|sdk|sdk-minimal|headless`. - **Pi**: repo is now `earendil-works/pi` (badlogic/pi-mono redirects), npm scope moved from `@mariozechner/pi-coding-agent` to `@earendil-works/pi-coding-agent`; version 1.x. Config home is `~/.pi/agent/` (seed `~/.pi/` is the parent); project dir `.pi/`.
- **Oh-My-Pi**: confirmed fork by Can Bölük (can1357), now under Stencil Labs; version 18.x; config home `~/.omp/agent/` with `config.yml` (YAML, not JSON); also reads Claude/Codex/Gemini/Cursor/Windsurf/VS Code/OpenCode project configs.

## 2. Per-harness security architecture

### 2.1 deepseek-harness (dsh)
- **Model**: "everything is a plugin" on Cordis; every capability (sandbox, approval, MCP client, credentials, telemetry, session log upload) is a plugin row in YAML patch layers composed bundle -> profile `cordis.patch.yml` -> home `cordis.patch.yml` -> `--patch`. Plugins are npm packages managed by pnpm via `dsh plugin`. They run in-process with full privileges (SAFETY.md says so).
- **Permissions**: two independent knobs, bundled by `@deepseek-ai/dsh-permission-presets`: sandbox mode (`read-only | workspace-write | danger-full-access`) and approval policy (`ask | never`). Base bundle: `DSH_PERMISSION_MODE` env, default `workspace-write` + `ask`; value `danger-full-access` sets approval to `never` (= reject; nothing is gated because the sandbox is open). Approval is one-shot per request, fails closed with no answerer (so headless denies). No per-command allow/deny lists were found.
- **Sandbox**: `dsh-sandbox-local`: bwrap (then Landlock) on Linux, Seatbelt on macOS, ACL runner on Windows (partial). Fails closed (`SANDBOX_UNAVAILABLE`). File-effects only: no network policy.
- **Trust**: executable config exists only under `$DSH_HOME`; repo content that is honoured: `AGENTS.md`/`CLAUDE.md`(+`.local.md`) chain and `.dsh/skills`, `.agents/skills`. No trust prompt.
- **Secrets**: `$DSH_HOME/.credentials.yaml` (lookup order: file > env > project `.env` > home `.env`); docs admit the agent's tool processes (same OS user) can read it. MCP stdio env is scrubbed.
- **Telemetry**: DeepSeek **session-log contributor uploads unaccepted session events with each DeepSeek API request by default** (opt-out setting); OTel via `DSH_TELEMETRY_*`.
- **Cross-harness**: first-party packages `subagent-claude-code`, `subagent-codex`, `subagent-acp` (T11 relevance: does a parent's permission mode propagate? Not verified; delegated children pin approval `never` per docs).
- **Web UI**: loopback `:3080`, launch token in URL -> signed cookie, Host-header fence, `--trusted-host`/`--public-url`/`--tls-*`.
- No SECURITY.md, no advisories; `SAFETY.md` disclaimer ("not security audited").

### 2.2 pi
- Philosophy: no permission system, no sandbox; SECURITY.md/`docs/security.md` say run it in a container/VM. Default tools read/bash/edit/write unprompted.
- **Project trust** (CVE-2026-54325 "loads project-local extensions without approval" is fixed in 0.79.0; docs describe the trust gate; that the gate is the fix is inferred): gates `.pi/settings.json`, `.pi/mcp.json`, `.pi/extensions|skills|prompts|themes`, `.pi/SYSTEM.md|APPEND_SYSTEM.md`, `.agents/skills`; default `defaultProjectTrust: "ask"`; non-interactive modes skip protected resources unless `always`; `--approve/--no-approve`; decisions in `~/.pi/agent/trust.json`. Context files (`AGENTS.md`, `CLAUDE.md`) and `sessionDir` are read before/without trust.
- Extensions are in-process TypeScript; packages installable from npm/git (`pi install`), pinned if versioned.
- Secrets: `~/.pi/agent/auth.json` 0600/0700, plaintext (CVE-2026-54327 write race, fixed 0.78.1). Telemetry: install/update ping + attribution headers (`PI_TELEMETRY=0`).
- 4 GHSAs/CVEs, all published 2026-06-08 (project-local extensions w/o approval; extension temp-path LPE; auth.json race; HTML-export XSS).

### 2.3 oh-my-pi (omp)
- **Default approval mode is `yolo`** (`tools.approvalMode`, source `tools/approval.ts` falls back to yolo). Modes `always-ask | write | yolo`; per-tool `tools.approval.<tool>: allow|deny|prompt`; `bash.patterns` rules; critical-pattern guard (`rm -rf /`, curl|sh...) forces a prompt only outside yolo. Docs: bash patterns are not containment, and the `eval` tool bypasses them.
- **No project trust**: source comment in `extensibility/extensions/types.ts`: "OMP performs no project-trust gating -- project-level settings and extensions load unconditionally". Project bases `.omp`, `.claude`, `.codex`, `.gemini` are all read; MCP imported from `.omp/mcp.json`, `.mcp.json`, `.claude`, `.cursor`, `.vscode`, `opencode.json`, Codex, Gemini, Windsurf. A repo that is merely a Claude Code project configures omp (hooks/extensions, MCP, skills, rules).
- `--trusted-extension <abs>` exact allowlist, `--no-extensions`.
- Memory backend opt-in (`off` default; `local`, `hindsight` remote, `mnemopi`, `sharpshooter`), injected into system prompt.
- Secrets in SQLite `agent.db`; secret obfuscation exists but `secrets.enabled` defaults off. Persistent `install-id` UUID (0600) sent as identity metadata to some providers/gateways.
- Installer verifies SHA-256 of prebuilt binary. No advisories published. SECURITY.md minimal.

### 2.4 kimi-cli (kimi-code)
- Modes (config key `default_permission_mode`): `manual` (default, "Always Ask"), `yolo` ("Ask When Needed": auto-approves regular calls, still asks for sensitive files like `.env`/SSH keys, `rm -rf`, plan exit; auto-approves MCP calls), `auto` ("Never Ask": everything). `[[permission.rules]]` allow/deny/ask with `Tool(arg-glob)`; `permission.dangerous_command_guard`.
- **`kimi -p` uses `auto` permission** (no approvals; static deny rules still apply); cannot be combined with `--yolo/--auto`. Treat `-p` in CI as unattended-full-access.
- Workspace trust prompt lists project MCP servers' launch commands; headless keeps project MCP disabled unless trusted or `KIMI_CODE_TRUST_WORKSPACE=1`. Hooks live only in `~/.kimi-code/config.toml` (fail-open). Config file is user-level only.
- Credentials: OAuth in `~/.kimi-code/credentials` (0700/0600); provider `api_key` may be plaintext in `config.toml`; env credentials are deliberately NOT read unless `api_key_env` or `KIMI_MODEL_*`.
- Auto-update installs by default (`tui.toml [upgrade] auto_install`). Telemetry default on (`KIMI_DISABLE_TELEMETRY=1`).
- `kimi web`: REST/WebSocket server, `#token=` URL credential, `KIMI_CODE_PASSWORD` when binding beyond loopback.

### 2.5 mistral-vibe
- Agents: `ask`, `plan` (read-only), `accept-edits` (**default**: edits auto, shell asks), `auto-approve`. Per-tool `[tools.<name>] permission = ask|always|never`, allowlist/denylist, `enabled_tools/disabled_tools` (glob or `re:`), global `bypass_tool_permissions` (default false), `--auto-approve/--yolo`.
- **Trust folder system** (`~/.vibe/trusted_folders.toml`, 0600): `.vibe/config.toml`, hooks, AGENTS.md, skills, tools, agents, prompts only load for trusted folders; `--trust` for one-invocation automation; `--worktree`/`--add-dir` imply trust.
- Hooks (`hooks.toml`, `pre_tool|post_tool|post_agent`) can rewrite tool arguments; subagents inherit hooks.
- Official composite GitHub Action (`action.yml`) runs `vibe -p "$PROMPT_INPUT"` (prompt via env var), no `--trust`, no `--auto-approve`.
- Telemetry on by default (`enable_telemetry`), OTel opt-in with redaction; daily update check prompts. No advisories.

### 2.6 hermes-agent
- SECURITY.md is unusually explicit: **only OS-level isolation is a boundary**; approval gate, output redaction, Skills Guard are heuristics. Supported postures: non-default terminal backend (docker/ssh/modal/daytona/singularity; confines only shell+file tools, not execute_code, MCP subprocesses, plugins, hooks) or whole-process wrapping (own Docker image, NVIDIA OpenShell).
- `approvals.mode: smart` (default; an auxiliary LLM auto-approves low-risk commands and auto-denies dangerous ones) | `manual` | `off`. `approvals.deny` globs and a hardline blocklist apply before yolo. Headless: `cron_mode`, `single_query_mode` (`hermes chat -q`), `unattended_mode` (webhook/API) all default `deny`.
- **Gateway authorization**: default deny; layered allowlists, DM pairing, `*_ALLOW_ALL_USERS`, `GATEWAY_ALLOW_ALL_USERS`.
- Memory: `MEMORY.md`/`USER.md` agent-written, cross-project, frozen snapshot per session; `memory.write_approval` default false.
- Extension points are "trusted by placement": gateway hooks dir (handler.py imported in-process), plugins (`plugins.enabled`), shell hooks (first-use consent per (event,command), keyed on command string not script hash). Project plugins `./.hermes/plugins` need `HERMES_ENABLE_PROJECT_PLUGINS=true`.
- Managed scope `/etc/hermes/{config.yaml,.env}` pins keys above user config and env (D14 = 3).
- Egress: optional iron-proxy credential-injection proxy (Docker backend only).
- 10 GHSAs with CVEs (May-June 2026): scanners (memory, context, skills guard), execute_code env sandbox issue, project-plugin env flag, `.env` sanitiser, compress_context, Feishu webhook DoS, WebSocket DNS rebinding, world-readable DB files. Several lack fixed versions; some NVD texts say vendor did not respond (third-party-report).

### 2.7 openclaw
- Gateway-centric (WS+HTTP on `127.0.0.1:18789`, auth required by default, token generated at onboarding; modes none|token|password|trusted-proxy). Channels (20+) with `dmPolicy` (`pairing` recommended; `open` is dangerous) and `allowFrom`.
- **Defaults are permissive for host exec**: `tools.exec.security=full`, `ask=off` on gateway/node hosts; sandbox **off by default**. Session permission modes read-only | guarded | workspace | full. Hardened baseline in docs sets `exec: {security: "deny", ask: "always"}`, `tools.fs.workspaceOnly`, sandbox on, `openclaw security audit`.
- Credentials: SQLite stores (`~/.openclaw/state/openclaw.sqlite`, per-agent DBs), `~/.openclaw/.env`, SecretRefs; docs say plaintext stays agent-readable.
- Memory: workspace `MEMORY.md`, `USER.md`, `memory/*.md`, `SOUL.md` (agent-writable, replayed into prompts).
- Skills: ClawHub registry with `openclaw skills verify` / Skill Cards; third-party reports of a malicious-skill campaign (341/2,857 flagged by Koi Security; later counts higher; secondary sources).
- Security record: 722 published GHSAs (14 critical, 249 high, 390 medium, 69 low; 39 carry CVE ids; 3 in Jan 2026 for `clawdbot`, 220 in Feb, 204 in Mar). Critical classes: scope/pairing escalation to `operator.admin` -> node RCE (6), sandbox escape/inheritance (2), CWD `.env` injection, env-sanitisation, plugin-install path traversal, voice-call allowlist bypass, Feishu webhook validation. Jan 2026 1-click RCE: Control UI trusted `gatewayUrl` query parameter and sent the stored token (GHSA-g8p2-7wf7-98mq, `clawdbot <= 2026.1.28`, fixed 2026.1.29).
- Exposed instances (Jan 2026, **third-party-report**): researcher Jamieson O'Reilly (Shodan fingerprint of the "Clawdbot Control" page; reverse-proxy auth bypass) and SlowMist alert reported hundreds of exposed control servers leaking API keys, bot tokens, OAuth secrets and chat logs (ForkLog 2026-01-27). Counts range from hundreds to 4,500+ across sources; original researcher write-up not fetched. Recorded with `verified=no`.

## 3. Headless / local-model recipes for the canary bench (not executed; docs-derived)

All seven accept an OpenAI-compatible Ollama endpoint (`http://<host>:11434/v1`), except OpenClaw which wants the native URL.

```yaml
# deepseek-harness: $DSH_HOME/profiles/headless/cordis.patch.yml  (then: dsh --profile headless "<task>")
- id: llm-pi-ai
  config:
    providers:
      ollama:
        apiKeyEnv: OLLAMA_API_KEY
        api: openai-completions
        baseURL: http://localhost:11434/v1
        models: [{id: qwen2.5-coder:7b}]
# default model is set by the agent-default-model row (provider/model); verify when wiring the adapter
```
```json
// pi: ~/.pi/agent/models.json   (run: pi --print --no-session --model ollama/qwen2.5-coder:7b "<task>")
{"providers": {"ollama": {"baseUrl": "http://localhost:11434/v1", "api": "openai-completions", "apiKey": "ollama", "models": [{"id": "qwen2.5-coder:7b"}]}}}
```

```sh
# oh-my-pi: omp -p --no-session --model ollama/<model> "<task>"   (implicit keyless Ollama discovery on :11434)
# kimi-code: no config file needed

KIMI_MODEL_API_KEY=ollama KIMI_MODEL_MAX_CONTEXT_SIZE=32768 kimi -p "<task>"

# hermes: model: {default: <model>, provider: custom, base_url: http://localhost:11434/v1} in config.yaml; hermes chat -q "<task>"

```
```toml
# ~/.vibe/config.toml (field names from vibe/core/config/models.py; spelling of the TOML array keys not run-tested)

[[providers]]
name = "ollama"
```

## 4. Linter rule fixtures (risky vs safe spellings)

## 5. Rule-engine implications
- Repo-level auto-load surfaces by harness: omp (everything, ungated, incl. foreign-tool dirs `.claude/`, `.cursor/`, `.vscode/`), pi (gated, except context files), vibe (gated), kimi (MCP gated), dsh (instructions+skills only), hermes (project plugins opt-in), openclaw (workspace in `~/.openclaw`).
- A scanner should treat `.claude/settings.json` hooks / `.mcp.json` in a repo as relevant to omp too (cross-harness inheritance), and `.agents/skills`, `AGENTS.md` as shared across pi, dsh, kimi, vibe, hermes (as context).
- Detect credentials: `~/.dsh/.credentials.yaml`, `~/.pi/agent/auth.json`, `~/.omp/agent/agent.db`, `~/.kimi-code/credentials/*.json` + plaintext `api_key` in `config.toml`, `~/.vibe/.env`, `~/.hermes/.env` + `auth.json`, `~/.openclaw/.env` + `openclaw.json` tokens; check modes (expect 0600/0700; Hermes and OpenClaw docs recommend chmod).
